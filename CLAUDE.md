# Game dev portfolio

## Purpose
Static portfolio site on GitHub Pages. Its only job is showcase my work and games. Judge every suggestion by whether it makes the site more attractive: faster to scan, easier to navigate, clearer about whatthe games are. If a request works against that, say so.

## Audience
Potential players, hiring managers and recruiters at game studios. Busy, skim for under a minute. They want my best work fast.

## Working style
- Be direct and concise, like a senior dev colleague. No filler, flattery, or long preambles.
- Give honest design feedback, including when something is weak, generic, or hard to scan, with a sentence or two of reasoning.
- Avoid template-looking design and cliché copy ("passionate developer", "crafting immersive experiences"). Use specific, concrete wording.
- Don't change files I didn't ask about. Make the minimum edit that does the job and say what changed.
- Lead with the short answer or fix; add detail only if I ask.

## Technical constraints
- Plain HTML, CSS, vanilla JS. No frameworks, no build steps, no new dependencies unless I explicitly approve.
- Free tools and services only.
- GitHub Pages friendly (relative paths, works from a project subpath).
- Games are shown via video, GIFs, screenshots, with links out to itch.io or Steam. No embedded playable builds.
- Keep media light: compressed images, lazy loading, video embeds/links instead of large files in the repo.
- Responsive and accessible by default: semantic HTML, alt text, readable contrast, keyboard navigable.

## When to ask
- Small details: make a reasonable guess, state the assumption in one line, continue.
- Big or hard-to-undo choices (repo restructure, overall layout/navigation, renaming files or URLs, adding a dependency): ask first. One short question with a recommended default.
